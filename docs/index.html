00psycho-journal-bot

"Every Sunday" really meant "about a week after the last restart."

The weekly report ran from an in-process timer that slept seven days from start-up. Every deploy, crash and reboot silently reset it. Nothing errored. The report simply arrived on a schedule nobody had chosen, and drifted a little further every time the box came back up.

psycho-journal-bot is a Telegram voice journal with a deliberately cold analyst attached: speak, it transcribes and stores, and on request it reads a window of what you actually said and tells you what it sees — without the encouragement.

01the drift

A sleep is not a schedule

The bug is not that the timer was wrong. It is that a timer measured from process start answers a different question than a calendar does, and the two agree right up until the first restart.

02the stance

What it is forbidden to say

Most of the prompt is a list of things the analyst may not do. That is the product decision, not a safety afterthought: an assistant that agrees with you is worse than no assistant, because you will believe it.

forbidden
generic praise
advice the entries do not support
emotional support for its own sake
— required —
a real citation, located: "Epictetus, Enchiridion §1"
never a platitude wearing a philosopher's name

It is an analyst, not a coach and not a therapist. It does not diagnose, and it says what the entries show even when that is unflattering — which is the only reason reading it back is worth anything.

03the ledger

Voice in, because nobody types a journal

A voice note is transcribed by Whisper and appended to a redis ledger keyed by timestamp. That ledger is the product; the model is a reader of it, and a late one. Nothing is analysed at write time.

Inputvoice note or text
TranscriptionWhisper
Storageredis, one entry per timestamp
Analysedonly when you ask
Analysis windowa period you name in words

Asking for "last week" parses to a window, the window selects entries, and only those entries become context. The bot has no memory of the conversation — it has a record of what you said, which is a different and more honest thing.

04the seam

The provider swap that touched one file

It ran on Anthropic. It had to stop. The migration changed which client a factory constructs — and nothing else — because the bot never depended on a vendor SDK, only on three methods.

05the gotcha

An empty answer with no error

Reasoning models spend tokens thinking, and that thinking is drawn from the same budget as the reply. Set the cap the way you always did and the model reasons right up to the limit, then has nothing left to say — so a request that cost real money returns an empty string and a success code.

Token capmax_completion_tokens
Reasoning tokensdrawn from that same cap
Cap set too tightempty reply, no error
temperaturenever sent

All three are documented in the adapter, on the lines where they bite. A note in a wiki nobody opens would not have saved the afternoon that found them.

06staying up

Two units, and neither can take the other down

The long-poll bot and the weekly report are separate systemd units. The report is a oneshot fired by a timer, so it cannot leak into the bot's process, and the bot restarting cannot reschedule it.

Botlong-poll service
Reportoneshot + calendar timer
Missed while offfires on boot
No systemd hostin-process fallback, opt-in

The in-process scheduler still exists behind an environment flag. It was not deleted because on a host without systemd it is the honest option — it just stopped being the default that quietly lied.

Scope, honestly: this one runs for anybody. It stores your entries in your redis and sends them to your OpenAI key — a Telegram token and that key are the whole list. The analyst's tone is somebody else's taste, and it lives in one prompt you are meant to rewrite.
